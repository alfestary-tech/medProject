# Alfestary DICOM Viewer

Приложение на PyQt6 для просмотра DICOM-срезов КТ, масок и дозы. При открытии папки пациента парсер подготавливает массивы изображений, контуров RTSTRUCT и дозы RTDOSE с учётом RTPLAN. В интерфейсе можно переключаться между срезами, смотреть данные пациента и два дополнительных вида изображения.

## Что реализовано

- **Просмотр DICOM:** список срезов, вкладки КТ, маски и дозы, виды спереди и сбоку из массива КТ, общий слайдер. Белая линия на дополнительных видах отмечает уровень выбранного среза.
- **Данные пациента:** имя, ID, дата рождения и тип исследования из первого DICOM-файла в отсортированном списке.
- **Аккаунты:** регистрация, вход и выход. Пароли хранятся в виде хешей Argon2; данные аккаунтов, папок и действий — в SQLite (`data/main.db`). При запуске проверяется дата последнего использования: если прошло три дня или больше, активная сессия завершается.
- **Интерфейс:** экраны просмотра, входа и регистрации оформлены общей графитовой темой из `styles/style.qss`.
- **КТ (`CT`):** для отдельной обработки срезы сортируются по координате, дубликаты удаляются по `SOPInstanceUID`, значения пикселей переводятся через `RescaleSlope` и `RescaleIntercept`.
- **Контуры (`RTSTRUCT`):** контуры сопоставляются со срезами КТ по `SOPInstanceUID`. Маски ROI строятся с помощью OpenCV; также есть вариант построения через scikit-image для сравнения.
- **Доза (`RTDOSE`):** чтение карты дозы и DVH, перенос дозы на сетку КТ с линейной интерполяцией.
- **План (`RTPLAN`):** чтение дозовых ориентиров, групп фракций, пучков и контрольных точек.

Обучения модели и генерации нового плана лечения в текущем проекте нет.

## Установка и запуск

Приведённые ниже команды выполняйте **из корня проекта**. Приложение находит `data/main.db` относительно расположения `utils/db_path.py`, поэтому его запуск не зависит от текущего рабочего каталога. Перед первым запуском скопируйте `data/main_example.db` в той же папке и переименуйте копию в `main.db`. Не заменяйте существующий `data/main.db` при повторном запуске: в нём хранятся ваши аккаунты и история.

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
if [ ! -f data/main.db ]; then cp data/main_example.db data/main.db; fi
python main.py
```

Windows (PowerShell):

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
if (-not (Test-Path data/main.db)) {
    Copy-Item data/main_example.db data/main.db
}
python main.py
```

После запуска зарегистрируйте аккаунт или войдите в существующий. В основном окне выберите **Файл → Открыть папку** и укажите каталог пациента, в котором вместе лежат КТ-срезы и `RS.dcm`, `RD.dcm`, `RP.dcm`. При чтении КТ эти три файла пропускаются. Срезы сортируются по координате `ImagePositionPatient`, повторные файлы удаляются по `SOPInstanceUID`. Переходить между ними можно слайдером или через список справа. Кнопка «Папка» показывает путь в строке состояния, «Выход» завершает текущую сессию.

Виды спереди и сбоку собираются из центральной строки и центрального столбца каждого среза массива КТ соответственно. Эти виды используются для навигации и не являются геометрической реконструкцией по координатам DICOM. Вкладка маски показывает все ROI вместе в чёрно-белом виде; вкладка дозы использует единую шкалу яркости для всего исследования.

## Подготовка КТ, контуров, дозы и плана

Для обработки нужны КТ-срезы и файлы RTSTRUCT, RTDOSE и RTPLAN. При выборе папки пациента интерфейс временно отделяет КТ-файлы и передаёт их вместе с путями к `RS.dcm`, `RD.dcm`, `RP.dcm` в `prepare_all_data()`. Пример структуры входных данных для интерфейса:

```text
datasets/Patient01/
├── CT_001.dcm          # КТ-срезы
├── CT_002.dcm
├── RS.dcm              # RTSTRUCT
├── RD.dcm              # RTDOSE
└── RP.dcm              # RTPLAN
```

Для прямого вызова парсера без интерфейса КТ-файлы должны находиться в отдельном каталоге `CT`: функция `prepare_all_data()` читает все файлы из переданного ей каталога. Тогда вызов выглядит так:

```python
from parser.parser import prepare_all_data

cts, masks, dose_on_ct, info = prepare_all_data(
    ct_dir="datasets/Patient01/CT",
    counters_filename="datasets/Patient01/RS.dcm",
    dose_filename="datasets/Patient01/RD.dcm",
    plan_filename="datasets/Patient01/RP.dcm",
)
```

| Результат | Содержимое | Форма |
| --- | --- | --- |
| `cts` | КТ после применения коэффициентов масштабирования. | `(Z, H, W)` |
| `masks` | Булевы маски ROI на сетке КТ. | `(Z, R, H, W)` |
| `dose_on_ct` | Доза, перенесённая на сетку КТ. | `(Z, H, W)` |
| `info` | Словарь метаданных КТ, ROI, дозы и плана. | — |

`Z` — число срезов, `R` — число ROI, `H` и `W` — высота и ширина среза. В `info["roi_channels"]` каждому каналу маски сопоставлены номер и название ROI. При общей обработке проверяется серия RTSTRUCT, единый `FrameOfReferenceUID` КТ и совпадение UID системы координат с RTDOSE и RTPLAN. Области КТ вне дозовой сетки получают нулевую дозу. `dose.resize()` также создаёт `valid_mask`, но `prepare_all_data()` сейчас её не возвращает.

Функция возвращает данные в памяти и ничего не сохраняет. Чтобы записать КТ и маски в `.npz`, а сведения о срезах и ROI в `.json`, вызовите функции сохранения отдельно:

```python
from parser import counter, scan
from parser.parser import save_ct_and_masks, save_info_json

cts, ct_info = scan.prepeare_CT_images("datasets/Patient01/CT")
counter.open_conture_dicom("datasets/Patient01/RS.dcm", ct_info)
masks = counter.collect_masks(cts, ct_info)

save_ct_and_masks(cts, masks, "output/Patient01_ct_masks.npz")
save_info_json(ct_info, "output/Patient01_info.json")
```

Здесь `save_info_json()` получает именно список `ct_info` из `scan.prepeare_CT_images()`, а не итоговый словарь `info` из `prepare_all_data()`.
